# Ricotta 2026-10-24.2

## Everyday ordering

- Supplier favourites appear within each supplier's list without duplicate quantity controls.
- Repeat an order and Undo remain available. Repeating historical items resolves explicit merges only when supplier/name/unit match unambiguously, and skips incompatible units or unavailable items.
- Before sending, review quantities at least three times the median of two or more recent comparable orders, and possible duplicate catalog entries in the draft. Ordinary orders have no new interruption. Warnings do not change quantities or send anything automatically.
- Supplier instructions are shared with the kitchen and visible during ordering and sending. They are kept separate from notes sent in WhatsApp.
- Deleting an item offers Undo. Its server snapshot expires after ten minutes, is bound to the account and device, and is pruned on deletion and nightly cleanup.

## Catalog and Rico

- Manage has a reviewed duplicate tool. Only matching names/search names with the same supplier and unit are suggested. The person chooses which item remains and approves the merge. Stale previews and incompatible metadata are refused. Draft amounts and favourites migrate atomically; historical order names/amounts are unchanged. Search names and notes are retained within existing limits.
- Duplicate review displays a bounded batch of up to 100 pairs, marked with + when more exist. Review again after resolving that batch.
- Rico previews show quantities before and after approval, including removals. A changed draft requires a fresh review. Overflowing quantities, unavailable items and changed units require a new proposal. Undo preserves unrelated newer edits and refuses to overwrite a subsequently changed quantity.
- Existing opt-in automatic draft filling remains; Rico still does not send orders to suppliers.
- Owner-only Admin diagnostics report API/database availability, safe scheduler summaries, local waiting orders and draft sync. Existing Devices shows app versions. No job SQL, credentials or internal error bodies are exposed.

## Approved interface

System typography, quieter grouped lists, restrained navigation translucency, the large green Order board, supplier search and filters, consistent quantity controls, phone editing sheets with visible Cancel/Save, centred desktop dialogs, aliases behind More options, and a desktop order summary alongside the list. Existing kitchen streak, Rico moods/notifications, ordering sounds, account permissions and optional locked Transfers remain. Tab searches and scroll positions are remembered within a session. Reduced Motion and Reduced Transparency are respected.

## Validation

Local checks cover all migrations, merge rollback/stale validation, Undo ownership/expiry/replay, browser database privilege denial, API authorization and error paths, Rico lifecycle and overflow, three-language text, production bundling, secret scanning and frozen Deno types. Source UI checks cover 198 workspace and 18 sign-in layouts. Production-build UI checks cover 66 workspace and 6 sign-in layouts. Source and production queue/search/new-feature integration checks use mock data, with no real supplier messages or business mutations.

The live migration was verified read-only: Undo RLS enabled; browser table access and internal RPC execution denied; four cron jobs enabled and no failures in the previous 24 hours. Actual iPhone hardware and signed-in production interactions were not exercised using the owner's credentials. Automated browser checks do not guarantee every device or future state is flawless.
